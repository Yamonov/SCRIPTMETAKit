# 実装レビュー記録 — 2026-11-03

追記: 2.0 リリースを前提とした後続レビューと現在の成果物・実行検証は
[Release2.0Validation.md](Release2.0Validation.md) に記録した。

対象は `codex/tags-localization` の Kit、C ABI、Swift SDK。
公開アプリ用 API の追加後、全体レビューと部分レビューを繰り返した。
製品バージョンは 1.3.3 を基にした開発版のまま。

## レビューの順序

1. 全体の責務・Swift からの公開範囲・既存 API の互換性を確認。
2. 設定変更、キャッシュの保持・無効化・復元、監視の状態遷移を確認。
3. タグと言語選択、編集時の全言語保全、文字コード・改行・コメント境界を確認。
4. 読み取り失敗と再試行、未解析のファイルの編集可否を確認。
5. 文字列編集とファイル編集の入力規則を照合。
6. 修正後に全体のテスト、Swift/C の対応、実スクリプトとの比較を再確認。

## 修正した問題

| 項目 | 修正内容と検証 |
|---|---|
| 稼働中の設定変更 | Rust の一括設定処理に検証・キャッシュ更新・保存待ち解放を集約。直接 `config_mut()` を使う従来経路も次の読み取り操作で反映。無効な設定では状態を変えない |
| 設定とキャッシュの対応 | 言語、解析条件、ファイル選別条件をキャッシュの文脈として検証。件数・時間制限の変更では、途中終了時に直前の正常な内容を残す |
| Swift での設定保持 | エンジン停止・再作成後に、言語以外の設定も維持。キャッシュ保存先のない Workspace は保存待ちを保持しない |
| キャッシュ取得元 | 永続化の無効化や catalog のみの無効化で、残るファイル一覧の「ディスクから復元・未確認」という情報を失わない |
| 再共有の索引 | 対象が空なら作らず、常駐用と保存待ち用に一つの索引を使う |
| Swift の一時配列 | タグと優先言語を C の借用バッファから直接変換。未使用の旧 C 宣言 6 個を削除 |
| 更新確認の入力 | 更新確認で使わない Description・Name・Author・編集状態等を Swift/C の受け渡しで再コピーしない。必要な ID・Version・Meta-URL・パスだけを渡す |
| コメント付き文字列生成 | ファイル保存と同じコメント文字の保護処理を適用。AppleScript の入れ子コメントの開始文字も保護。合成ソースをコンパイルして確認 |
| 項目・ブロック境界 | 単一行の項目の改行、外側の終了マーカー、LF/CR/CRLF の Description 終了行を保存前に拒否。配布メタデータにも適用 |
| 旧形式の一行中の項目 | 値の一部が別項目と解釈される曖昧な入力を保存前に拒否。新形式で保護される Name/Author の通常の本文は維持 |
| 未解析の `.scpt` | キャッシュの再利用だけで `unknown` が `appendable` に変わる誤判定を修正 |
| 読み取り失敗 | 本文を取得できていない間は編集・追記可能としない。ファイルのサイズ・更新日時が同じでも、失敗した読み取りは次のスキャンで再試行 |
| 文字列編集とファイル編集 | 空の URL・バージョン、省略形の URL、不正な URL を同じ規則で処理。Swift から双方の出力を比較 |
| Description の書式 | 別項目だけを編集したときも、本文冒頭の字下げ・末尾の空白・空行を維持。LF/CR/CRLF と新旧形式で往復を確認 |
| 重複した処理 | 改行の正規化を共通化し、LF のみなら本文を複製しない。編集時の不要な Description の全解析と、設定既定値・検証規則の二重定義を除去 |

`tests/review_regressions.rs` は、コメント境界・改行・項目混入・未解析状態・
読み取り失敗の復旧を検証する。修正前に失敗するテストを実行し、問題を再現した。
`tests/ScriptMetaKitTests/ServiceAPITests.swift` と FFI の services テストは、
それらが Swift/C 境界でも同じ扱いになることを確認する。

## 意図した責務と検証範囲

- OS の優先言語を取得するのは利用アプリ。Kit は受け取った言語順だけを使う。
- 通常結果は選択した言語だけを保持し、編集時に全言語を読み込む。
- アプリ用の接点は Engine / Workspace / Metadata に整理。監視計画や任意の
  キャッシュ Data の操作など、内部部品をすべて Swift に公開する方式にはしない。
- 低レベルの Rust scanner に直接 candidate cache を渡す場合、同じ読み取り設定の
  キャッシュを渡す責任は呼び出し側にある。Engine はこの対応を管理する。
- 言語変更後の再スキャンと、アプリ UI への結果の採用は利用アプリが管理する。
  `ScanResult.preferredLanguages` で結果の言語設定を識別できる。
- テストは Apple Silicon 上の Kit と合成ファイルを対象とする。AppleScript は
  合成ソースのコンパイル・読み取りのみで、スクリプト本体を実行しない。
- 実際の Scripta!/Adobe UI、Intel、Windows は今回の実行検証範囲に含めない。

最終の全体・部分レビューで、今回の範囲に未解決の指摘は残っていない。
Rust/C 354 件、Swift 85 件が通過し、公開 API だけを使う Swift 6.2 の
Release クライアントもビルド・実行できた。対応する SDK と比較結果は
[SwiftApplicationAPIValidation.md](SwiftApplicationAPIValidation.md) に記録した。
