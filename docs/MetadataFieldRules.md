# メタ項目の必須条件と関係（2.1.0）

これは Kit がメタデータを保存する際の条件です。既存ファイルの読み取りは互換性のため不完全な記述も扱い、必要に応じて診断情報を返します。読み取れたことと、新規保存の条件を満たすことは同じではありません。

| 項目 | 通常形式での保存 | 多言語形式での保存 | 関連する条件 |
| --- | --- | --- | --- |
| `Script-ID` | 必須 | 必須 | 空白だけでは不可。他ファイルとの重複確認は別の公開 API で行う |
| 素の `Name` | 従来形式との互換性のため任意 | 必須 | 多言語形式では既定言語の名前。空白だけでは不可 |
| 素の `Author` | 任意 | 任意 | `Edit-Password-SHA256` を指定する場合は必須。多言語形式では既定言語の著者 |
| `Description`／`Description-BEGIN` 本文 | 任意 | 任意 | 空欄も許可。本文に言語区切りを使う場合は有効な既定言語が必要 |
| `Meta-Default-language` | 任意 | 必須 | 有効な BCP 47 言語コード。内容の言語を推測して自動設定しない |
| `Name[言語]` | 使用するなら多言語形式 | 任意 | 空の宣言も保存する。既定言語の素の Name の代用にはしない |
| `Author[言語]` | 使用するなら多言語形式 | 任意 | 空の宣言も保存する。パスワード付き保存の素の Author の代用にはしない |
| `Tags` | 任意 | 任意 | 独立した共通項目。Name・Author・Description・既定言語を要求しない |
| `X-作成者ID-項目名` | 任意 | 任意 | 独立した共通項目。必須条件と表記は [独自拡張タグ仕様](CustomMetadataFields.md) に従う |
| `Version` | 任意 | 任意 | 指定する場合は Kit が扱えるバージョン形式 |
| `Target-App` | 任意 | 任意 | Tags や多言語設定とは独立 |
| `Min-Target-Version` | 任意 | 任意 | 指定する場合は Kit が扱えるバージョン形式 |
| `Meta-URL` | 任意 | 任意 | 指定する場合は Kit が扱える URL。更新確認に利用する |
| `Release-Date` | 任意 | 任意 | Tags や多言語設定とは独立 |
| `Edit-Password-SHA256` | 任意 | 任意 | 有効なハッシュ形式と、空白ではない素の Author が必要 |

ここでいう多言語形式は、言語別項目や既定言語を明示して編集する形式です。言語が一つになっても、その言語を明示する形式を維持する間は既定言語指定を保持します。通常形式への解除を実行した場合は、言語指定を取り除きます。

## Tags は任意の独立項目

- Tags があっても、多言語対応を有効にする必要はありません。
- Tags があることを理由に Name や `Meta-Default-language` を必須にはしません。
- 多言語対応を使っていても、Tags を付ける必要はありません。
- 言語の追加・変更・削除・解除は、Tags を変更する操作ではありません。
- Tags は言語別に分けません。複数の `Tags` は記載順に結合し、同一の値を重複除去します。
- カンマ前後の空白は除き、タグ内部の空白は保持します。末尾カンマは続行を許し、空のタグは生成しません。
- 項目やブロック境界と区別できない文字列はタグ名に使えません。詳しくは [Tags とローカライズ](TagsLocalization.md) を参照してください。

例えば、次の記述は保存できます。

```text
SCRIPTMETA-BEGIN
Script-ID=example.tags
Tags=image,画像
SCRIPTMETA-END
```

## 既定言語と編集操作

| 操作 | Name・Author・Description | `Meta-Default-language` | Tags・未知フィールド・他のメタ情報 |
| --- | --- | --- | --- |
| 通常形式の読み込み | 言語未指定の実データとして保持 | 元にない場合は設定しない | 保持 |
| 最初の既定言語を明示 | 通常値を指定した言語に関連付ける。競合する別の値があれば拒否 | 明示された値を設定 | 保持 |
| 既定言語を変更 | 旧既定言語の内容もその言語として残す。新既定言語の実データを素の項目に使う | 新しい既定言語へ変更 | 保持 |
| 追加言語を削除 | 指定した言語の三項目を削除 | 維持 | 保持 |
| 既定言語を削除し、他言語が残る | 指定した言語の三項目を削除 | 旧指定も削除対象。新しい既定言語を明示するまで保存不可 | 保持 |
| 最後の既定言語を削除／解除 | その内容を素の Name・Author・Description として残す | 削除する。空の言語行も自動追加しない | 保持 |

新しい既定言語の Name がない場合、他言語で埋めません。編集状態として保持し、保存前に入力を求めます。Author と Description は任意ですが、パスワード付き保存など上表の条件は引き続き適用します。

最後の既定言語を解除した結果は、例えば次の通常形式です。

```text
SCRIPTMETA-BEGIN
Script-ID=example.export
Name=画像を書き出す
Author=作者
Tags=image,画像
X-Custom=保持する値
Description-BEGIN
画像を書き出します。
Description-END
SCRIPTMETA-END
```

`Meta-Default-language` がない Description は全文を通常テキストとして扱います。先頭の `[en]` 等も文字であり、バックスラッシュもそのまま保持します。有効な既定言語がある場合に限り、Description 内の有効な言語ラベルを区切りとして扱います。

## 空の言語と API の保持指定

追加言語の三項目がすべて未入力でも、その言語を保存・再読み込みで保持します。完全に未入力の言語は `Name[fr]=` のような空の宣言を使えます。通常表示では空の翻訳を選ばず、編集 API ではその言語の実データだけを返します。

既存 API の `extensions = nil` は「保持」のままです。言語指定を削除する意味には変更しません。最後の言語を解除する場合は、新しい編集 API が内容を移し、言語指定を削除した明示的な draft を作ります。Tags を明示的に空配列へ変更する操作は、言語解除とは別に Tags を削除する指示です。

ファイル保存は既存の編集セッション、外部変更検知、バックアップを通します。未知フィールドを保つ編集には元のファイル／元の本文を使う保存 API を利用し、draft だけから作る単独の render 結果でファイル全体を置き換えないでください。

公開 API の利用例は [多言語編集 API](LocalizationEditingAPI.md) を参照してください。
